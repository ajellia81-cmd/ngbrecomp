# Experimental iOS Smooth Motion

The guest simulation, vblank, audio and visibility queries remain at 60 Hz.
Smooth Motion renders a separate intermediate scene for a high-refresh display.
The geometry matching and interpolation algorithm is now the unchanged VF3
implementation; the former shader-constant-bank matcher has been removed.

## Exact VF3 code

The reference is `ajellia81-cmd/vf3-recomp`, commit
`a8473a99091e6bb207c85d6d247eece8c4866b39`:

- `third_party/vf3_scene/r3d_scene.h` and `r3d_scene.cpp` are unchanged copies.
- `interpolate.cpp` extracts the original matrix operations and entire scene
  interpolation section without changing their code or thresholds. Model3's
  hardware reader is not compiled into the Xbox renderer.
- `tests/check_vf3_reference.py` checks the pinned reference hash and exact
  extracted implementation. The original MIT notice is bundled with the app.

This reuses VF3's viewport/model pairing, repeated-resource handling, inferred
camera motion, matrix and compatible vertex interpolation, cached pairing and
scene-cut policy. It does not reproduce Model3 hardware or its scene-memory
reader: NGB supplies the scene through the adapter below.

## NGB scene adapter

`src/d3d/gpu/scene_motion.cpp` snapshots the main camera and converts each
eligible draw into owned model-space geometry, model-to-view matrices and a
viewport. A model resource may have several visible instances, just as in VF3.
Draw order is not used as instance identity.

The original vertex program's position calculation is evaluated from the actual
vertex declaration, streams and constant bank, including relative bone addresses.
A backwards slice omits calculations that do not affect position. The resulting
positions are unprojected into the scene's model coordinates. Deformed geometry
gets its actual posed spatial center; it is not represented by arbitrary uniform
values. Fixed-function transforms and vertex blending have a separate position
calculation matching their original shader path.

Fixed-function rigid terrain uses the exact matrices already supplied by the
renderer and retains its immutable model-space mesh. It no longer performs
per-vertex screen conversion, inverse projection and unnecessary deformation
blending. For programmable rigid geometry the adapter proves the complete
position transform algebraically and likewise retains shared meshes. Fixed
skinning prepares state and bone matrices once per draw; implicit and explicit
weights preserve the original homogeneous point calculation. Nonlinear
programs keep the original evaluator. Perspective reciprocals retain finite-domain
checks; failed algebra cannot become a fabricated transform.

Fixed-function immutable input caching additionally compares owned stream bytes,
vertex declarations, decoding, topology and indices before reusing expanded
geometry. Reallocated streams with identical contents can reuse it; mutations at
the same address cannot. Transforms remain per-draw. Input/geometry cache storage
and the existing rigid-mesh cache each have a 32 MiB bound. The
`unchanged input draws` counter reports this fast path.

The unchanged VF3 function produces the intermediate geometry. The adapter
projects that result into an owned vertex buffer read only by replay shaders.
Draws sharing a model pose and geometry share that result across material/depth
passes, including EQUAL-depth passes. Endpoint constants and geometry are never
modified. Colours, lighting, texture coordinates and other material varyings
still come from the original NGB vertex program; this is not a transplant of
VF3's complete renderer or all of its material animation behavior.

## Rendering and presentation

The authoritative guest frame is rendered normally. Owned vertex/index data,
pipelines, descriptors and ordered clear/draw/copy recipes are retained. Replay
uses isolated single-sample colour/depth targets and remaps render-target feedback;
it does not overwrite guest-visible pixels or run guest visibility queries.
Offscreen effects retain their original draw recipes.

Original and intermediate commands use the same ordered Vulkan queue. The
presenter shows midpoint and endpoint images at display cadence, retaining source
leases until their copy fences complete. The guest does not wait for two display
acquisitions or run at double speed. Lifecycle, resize and long gaps reset scene
history. Movies and 2D menus use the authoritative rendering path.

The vertex buffer uses a distinct read-only storage binding. Endpoint shaders
leave its override disabled; replay shaders consume the scene result. The upload
ring reserves a whole draw, including these positions, inside one 32 MiB frame
slot. Capture packets are capped at 96 MiB, owned scene geometry at 64 MiB and
replay target allocations at 256 MiB. Resource/graph failures retain normal
rendering. Four consecutive replay-associated guest intervals above 25 ms
(and below the 100 ms suspension boundary) trigger a 12-guest-frame recovery
window, replacing the earlier two-spike/120-frame pause. Isolated targets remain
allocated during this short recovery and its warm-up frame; snapshots are
refreshed before replay resumes. Scene history still resets, so frames on either
side of the pause are never interpolated together.

## Settings and validation

Smooth Motion requires a reported display cadence above 100 Hz, MSAA Off and
Smoother Glow Off. It does not change the selected rendering resolution or
guarantee sustained 120 fps. Boot/title menus can remain at their original rate.

`[Smooth Motion VF3 scene/5s]` reports models, shared passes, unsupported draws,
posed-center fallbacks, proven rigid transforms, retained meshes, VF3 matches,
vertex blends, cuts and CPU conversion/interpolation time. Presenter output and
guest swaps are logged separately. Counters alone do not prove artifact-free
on-screen motion. `[Smooth Motion CPU/5s]` splits extraction, VF3 interpolation
and projection time, with fixed-rigid/skinned draw and interpreted-vertex counts.

Native tests check the actual adapter with camera translation, reordered repeated
instances, shared depth passes, relative bone addressing, raw SHORT3 input,
nonlinear-program rejection, finite-domain RCC, immutable geometry and history
reset. Fixed-function cases additionally check reordered instances, material-pass
agreement, ignored point W, immutable terrain reuse, and all six blend modes
including explicit weight sums other than one. Input-cache fixtures cover stream
relocation, mutations of positions/UV/indices, decoding changes and independently
changing transforms. Recovery fixtures distinguish brief spikes, sustained
replay overload, original-only frames and long suspension gaps. CI compiles the real fixed/program/raw-decoded replay wrappers to SPIR-V,
builds the iPhoneOS renderer and links/packages the actual game engine. Local
address/undefined-behavior checks pass; leak checking is unavailable under the
cloud environment's tracing setup.

The implementation has not been run on a physical iPhone in this environment.
Remaining device checks are flicker/geometry correctness in the reported scenes,
CPU/GPU frame time, lighting/shadow appearance, lifecycle resume and extended play.
The accepted Korean glyphs, spacing and Settings tab asset are preserved.
